# Diff view for PI-Desktop

面向 **PI-Desktop 0.17.0+** 的本地变更审查插件。**会话修改**按用户轮次保存证据、展示文末卡片与输入框上方浮窗；**本地 Git** 是独立入口，不作为会话修改来源。

> **1.4.5 支持勾选文件直接 Commit。** 工作区提交所选文件当前内容，暂存区提交所选索引内容，均创建真实 Git 历史；摘要必填、描述选填，不夹带未勾选暂存。差异预览独立加载、缓存和去重，不再锁住整页；选择栏与文件行对齐，逐文件显示真实 `+N / -N`。见 [1.4.5 验证记录](docs/verification-1.4.5.md)。

> **1.4.4 更新本地 Git 界面。** 文件行复用会话修改的类型图标与路径层级，支持行内差异与顶部一键折叠；暂存/取消暂存、撤销使用图标。工作区与暂存区底部固定必填提交摘要，文件和差异独立滚动，不遮挡提交区；其他 Git 页面不显示提交框。仍只提交暂存区，保留 hooks 与确认机制。见 [1.4.4 验证记录](docs/verification-1.4.4.md)。

> **1.4.3 优化连续 diff 的无感更新。** 再次修改当前文件时，新差异先在后台补齐已加载范围再一次性更新，避免长差异缩回首屏后重新加载；位置变化的差异块复用界面节点与折叠状态，保留视口、文本选择和键盘焦点。见 [1.4.3 验证记录](docs/verification-1.4.3.md)。

> **1.4.2 修复临时会话记录与侧栏闪屏。** 未打开工作区也记录本会话临时目录的真实 Write/Edit 证据；侧栏后台更新不清空、不闪屏，不随轮询禁用复制。文件按首次记录的时间顺序展示，新文件追加，卡片点击只定位；Git/会话页签切换保留内容与折叠状态。见 [1.4.2 验证记录](docs/verification-1.4.2.md)。

> **1.4.0 更新变更审查侧栏。** 胶囊式轮次与统计、紧凑文件行、文件类型图标、逐行打开/更多菜单；PNG、JPEG、WebP、SVG 等图片不再记录或参与变更统计。已有图片记录也不再出现在审查中，真实文件和独立本地 Git 状态不受影响。见 [1.4.0 验证记录](docs/verification-1.4.0.md)。

> **1.3.3 修复重启后差异证据丢失和历史退化。** 去正文的结构化工具证据按会话/项目持久化；空 transcript 不擦除旧证据，缺失的原生快照可由同会话哈希验证的历史 blob 补齐。见 [1.3.3 修复记录](docs/verification-1.3.3.md)。不会写宿主数据库或恢复没有来源的聊天正文；真正缺失或归属不明的历史仍标为未知。

> **可信插件，非沙箱。** 恢复会写工作区，Git 管理会写索引/提交/分支/stash；操作由你发起，危险操作需要确认。无远程 Git、网络请求或自动聊天发送。仓库 hooks/filters 是受信任本地代码。

## 安装与第一次审查

1. 本地目录安装：保持现有 `plugin/` 路径，构建更新后在插件页手动 **reload** 即可，无需重新安装包。包安装可选择 `plugin/dist/local.diff-view-1.4.5.piplug`。
2. 手动检查并批准权限。本次未自动安装、reload、授权或修改宿主记录。
3. 在当前会话右侧添加 **差异审查 / Diff view**。无会话身份时不会回退显示全局历史；独立窗口仍可使用本地 Git。
4. **会话修改**使用“对话轮次”选择历史，卡片点击打开对应快照；**本地 Git**查看状态、暂存、提交、分支、历史、blame 与 stash。
5. 已捕获运行任务显示输入框上方浮窗，结束后由回复卡片承接。修改后恢复原状仍保留事件且净行数为零。非文本/缺失证据明确标注，未知归属不计入确定行数。

初始空仓库没有 HEAD 时可查看新增/暂存内容；提交和分支对比需要真实提交。非 Git 项目仍可查看可靠采集的轮次。不自动初始化用户项目的 Git 仓库。

## 完成一次审查

- 选择文件，切换统一/左右布局；展开已有上下文、启用换行、搜索文件或复制标准 unified diff。
- 在 diff 行上点击评论按钮。评论记录路径、版本指纹、新旧侧行号和真实代码片段；刷新后版本不匹配的评论标为失效。
- 在侧栏或独立视图中审阅逐行评论并复制反馈，由你手动粘贴和发送；不会改动已有草稿。当前侧栏桥接没有直接回填输入框的公开接口。
- **本地 Git**支持单文件/显式批量暂存与取消暂存；工作区撤销恢复索引版本（未跟踪文件确认后删除，确认后文件/索引变化会拒绝）。勾选文件并填写必填摘要，可选展开描述，确认 **Commit** 后直接进入历史：工作区使用当前文件内容，无需先暂存；暂存区使用所选索引内容。未勾选的工作文件和暂存内容保留。另支持安全分支创建、切换、重命名、删除；历史/差异、blame 和 stash。脏工作区阻止切换，stash 冲突不会误报成功或删除原 stash。
- 完整已结算的新版工作区内任务支持文件级撤销与重新应用；旧版历史、工作区外文件、归因不完整或冲突记录始终只读。
- 扩展上下文后片段可能合并，hunk 操作只在默认三行上下文时提供。
- 文件列表上方可对当前搜索结果执行批量操作（最多 20 个可操作文件）。确认中列出实际路径，结束后逐文件显示成功或冲突；不保证跨文件原子。

“暂存”和“撤销”不是同义词。暂存只改变索引；撤销改变文件。每次操作要求确认并重新验证版本；外部变化时需要重新审查，不提供强制覆盖。

## 数据和权限

| 项目 | 实际行为 |
|---|---|
| `ui.view` / `ui.panel` | 右侧视图与独立窗口 |
| `agent.extension` | 工具执行前后采集真实内容；在 Agent 进程运行，没有 OS 沙箱 |
| `renderer.extension` | 公开回复和输入区插槽；只读所属输入框位置及当前会话运行元数据，在插件自己的区域显示胶囊；用户点击时复用经契约核对的内部插件页签接口，不读消息正文或改写宿主记录 |
| `clipboard.write` | 复制 diff / 评论，无剪贴板读取 |
| 文件和 Git 操作 | 插件自行执行 Node/Git 适配器，**不是宿主 fs 网关逐次授权** |
| 本地存储 | `pi.plugin.getDataPath()` 指定的私有目录，内容寻址快照、去正文工具证据、评论、恢复副本和日志 |
| Agent/main 桥接 | `~/.pi-diff-view/locators/<安装路径哈希>.json`，只有协议、数据目录和实例 generation；实例卸载时清理自身定位信息 |

文件工具捕获明确普通路径；Shell/Bash 使用有界工作区前后快照，Task/TaskWait 采样保守标注。历史恢复只读授权会话的 JSONL 和原生 review-changes 证据，不修改宿主、不使用当前磁盘或 Git 重建旧版本。未知内容保留缺失状态。外部文件只读；拒绝凭据、私有数据、依赖/内部目录、设备路径及链接逃逸。

文本上限 **2 MiB/文件**；单轮最多 256 个捕获路径；历史最多 200 轮；快照容量 **128 MiB**；恢复副本 **64 MiB/最多 1000 条文件记录**。大文件/二进制/特殊文件只显示元信息。容量达到限制时采集停止并警告，先停止 Agent 再清理本插件历史。清理历史会删除恢复副本，之后不能恢复已清理的版本；跨进程锁防止与新采集写入同时清理。项目源码、Git 提交和原插件不受清理影响。

结构化工具证据另限 **8 MiB/会话项目、200 份、总量 128 MiB**；容量不足报错，不静默删除旧会话。清理插件历史也会删除这些证据及内存缓存。插件不是聊天备份工具，宿主丢失正文不能由去正文证据恢复。

## 支持边界

[兼容性和 Codex 对照](docs/compatibility.md)列出限制。特别注意：

- Shell 快照限 256 文件、4096 目录项、16 MiB 文本及约 3 秒扫描预算；后台延迟写入、未结束 Task、未参与租约的外部作者不保证覆盖。不能证明的并发记录保守标记归属不明。
- 移动可能表示为源删除与目标新增；净零事件保留，但不提供无意义回滚。未留下历史证据的内容无法恢复。
- 原生历史优先按用户/回复消息 ID 关联；旧插件快照仍支持唯一指纹与时间匹配。旧记录缺少 ID 时不按时间随意合并来源。
- 独立 Git 管理执行本地配置的 hooks/filters；旧只读差异适配器对特殊过滤状态仍保守处理。无 fetch/pull/push、merge/rebase 或强制分支删除。
- 恢复先移走并核对实际目标，再独占安装；冲突不覆盖新出现文件。恢复记录和原文件副本留在私有 backups；若无法把实际原文件放回，错误会指出项目内 `.diff-view-*.original` 恢复文件，切勿删除它。整个操作不是 OS 级事务，仍应停止同时编辑该文件的外部进程。

## 本地开发和检查

```bash
npm ci --ignore-scripts
npm run typecheck
npm test
npm run build
npm run test:e2e
```

构建输出在 `plugin/`。运行界面测试前需要本机 Chromium 或 Playwright 浏览器；测试临时仓库/浏览器工件使用 `PI_SCRATCH_DIR`，不在用户项目制造样本文件。

在 PI-Desktop 中使用官方 **PluginCheck** 校验 `plugin`，使用 **PluginPack** 打包；不要手工 zip，安装器只接受 store-only `.piplug`。本版修复、测试和边界见 [1.4.5 验证记录](docs/verification-1.4.5.md)；旧版文档保留为历史说明。

性能复现与边界见 [v1.1.0 加载优化](docs/performance.md)。
