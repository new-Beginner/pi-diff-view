# 1.4.5 本地 Git 修复验证

本版将勾选文件的 Commit 与暂存明确分开：Commit 创建真实提交并进入历史。没有自动安装或 reload；原生 PI-Desktop 窗口仍需用户手动验收。

## 勾选文件直接提交

1. 在工作区或暂存区勾选文件。
2. 填写必填的单行摘要；需要时展开可选描述。
3. 点击 **Commit** 并确认范围。
4. 成功提示显示提交 ID，可点击“查看历史”。

工作区提交所选文件的当前内容，无需先暂存；暂存区提交所选索引内容。两者都不夹带未勾选的暂存内容，也不改写未勾选的工作文件。摘要限制 240 字符，描述限制 4500 字符；拒绝空白摘要、摘要换行和 NUL。Commit 使用隔离索引并运行真实 Git hooks，不使用 `--no-verify`。

提交成功后只同步所选索引项。真实索引在 hooks 期间被外部修改时保留外部写入并明确提示核对；同步失败也明确报告“提交已成功”，避免用户重复提交。hooks/filters 仍是受信任本地代码，可能自行修改文件。

## 差异卡顿原因与修复

| 证据 | 原因 | 修复路径 |
|---|---|---|
| 原差异读取共用全局 busy | 只读请求禁用整页，插入“正在执行 Git”并改变布局 | `useGitPreview.ts` 独立状态，慢请求只在行内提示 |
| 重复打开文件重新请求 | 反复等待 Git 和宿主桥接 | 20 项缓存、进行中请求去重、120ms 悬停/焦点预取 |
| 工作区预览扫描完整 status | 单文件打开承担整仓库路径检查 | `local-management.ts` 仅对目标路径运行 `ls-files` |
| 文件行原无统计接口 | 无法展示真实增删数 | 有界 `numstat -z`，未跟踪文本按快照统计 |

180ms 内完成的预览不显示加载文案。快速切换或折叠时旧请求不会覆盖新选择；刷新和写操作清除预览缓存。外部编辑后应点击刷新，缓存不会自动监视磁盘。后台作业、桥接限流和超时保护保留，不承诺 Git/hooks/磁盘零延迟。

## 文件列表与统计

选择栏改为与文件行复选框对齐的全选框、已选计数及图标操作，不再堆放一排文字按钮。文件右侧显示绿色 `+N` 和红色 `-N`；二进制、大文件或读取失败明确标注，不伪造为零。统计每批最多 80 路径，独立加载，不禁用界面。

工作区统计比较索引与工作树；暂存区比较 HEAD 与索引。部分暂存文件的工作区统计不是 HEAD 到工作树的总变化。固定提交区只在工作区/暂存区显示，文件与差异区域独立滚动。

## 复现

在已有依赖的项目根目录执行：

```bash
npm run typecheck
npm test
npm run build
E2E_BROWSER='C:/Program Files/Google/Chrome/Application/chrome.exe' npx playwright test
```

随后使用 PI-Desktop 的 **PluginCheck** 和 **PluginPack** 校验及打包 `plugin`。安装包和最终验证结果记录在 `release-1.4.5.json`。

## 使用边界

没有新增权限；`agent.extension` 与 `renderer.extension` 仍需显式授权。会话修改、分支、历史、Blame、Stash 和原有安全确认保留。受保护、冲突、链接及非普通文件继续拒绝操作。请手动 reload 本地 `plugin/` 或安装 1.4.5 包后检查原生窗口；本次没有修改宿主历史。
