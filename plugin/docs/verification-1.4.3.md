# 1.4.3 连续 diff 静默更新验证

> 本地目录安装需在插件页手动 reload 一次以加载新版；包安装使用 `plugin/dist/local.diff-view-1.4.3.piplug`。本次不自动安装、reload 或修改宿主历史，不增加权限。

## 修复原因与行为

1.4.2 已保留文件列表，但选中文件再次修改时，新的差异首屏仍会替换已经加载的长差异，导致后续行和差异块短暂消失、再分页加载。差异块的后端 ID 还包含序号与行位置，前面的新增修改使 ID 变化后会重新挂载节点。自动跟随新轮次时也会重新显示加载状态。

1.4.3 保留当前显示内容，先在后台准备新差异，覆盖已加载行与旧文件锚点范围，再一次性更新列表与差异。若旧差异已经加载完整，则新差异也先加载完整。后台准备仍使用每页最多 80 行的有界传输；期间可以继续查看、复制、折叠和改变上下文。

- 界面差异块按旧文件锚点匹配并复用节点，不用后端 hunk ID 作为 React key。
- 操作仍使用最新的后端 hunk ID、版本指纹与原有确认流程；界面 key 不参与 Git 或恢复动作。
- 更新时保持视口锚点及横向滚动；未变化行复用内容，保留文本选择与键盘焦点。
- 自动跟随新轮次也先准备内容，不先清空旧差异；手动更换文件、范围或上下文仍保持原有行为。
- 后台准备期间改变目标或上下文，会重新核对当前目标；准备失败则保留原有完整视图，显示可重试错误，不发布半成品。

## 证据与验证

| 测试证据 | 发现 | 修复路径 |
| --- | --- | --- |
| 新增浏览器用例在旧版运行时失败，长差异退回前 80 行、后续块消失 | 元数据先发布、首屏差异后替换造成可见重载 | `prepareDiffDetail` 与 `ReviewApp` 的后台准备、统一发布 |
| 新增/移动差异块后折叠状态丢失 | React key 直接依赖变化的后端 hunk ID | `live-diff.ts` 的旧文件锚点匹配与独立界面 key |
| 自动新轮次、连续三次更新检查 | 旧视图不能在等待期间清空或縮短 | `silent-diff-update.spec.ts` 的节点连接、完整行与视口监测 |
| 文本选择、焦点、上下文并发变化和准备错误用例 | 无感更新不能破坏正在进行的交互 | 最新目标核对、稳定节点、缓存复用与失败保留 |

最终验证结果：

- 类型检查、离线构建和 `git diff --check` 通过。
- 单元/集成：35 个测试文件，294 项通过；1 项 POSIX FIFO 测试因 Windows 不适用跳过。
- Chrome 全量浏览器回归：101 项通过，其中新增静默更新专项 6 项，原有侧栏稳定性 6 项。
- 新增单元测试 10 项覆盖完整/部分分页预加载、旧文件锚点覆盖、取消、非法分页、差异块移动/新增/合并/拆分和后端 ID 保留。
- 原有会话隔离、复制、卡片定位、分页、撤销/重新应用、独立 Git、主题、运行浮窗等回归全部通过。未修改这些功能的后端实现。

## 验收边界

测试使用生产侧栏 bundle 与模拟宿主桥接；Git 场景另使用真实临时后端。未自动重载用户运行中的插件，也未声称完成当前 PI-Desktop 原生窗口验收。首次加载、用户主动切换目标、真实内容被删除和需要报告的错误仍会产生必要的界面变化；优化的是后台更新导致的空白、加载切换、节点重建和滚动回跳，不隐藏实际新内容或错误。
