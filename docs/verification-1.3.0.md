## 问题解释：证据 → 结论 → 修改

### “选择已过期”

**代码事实：** 原导航只存在主进程内存，按 30 分钟和 32 个会话淘汰，并依赖进程级 activeSession。重载丢失令牌，多窗口可互相影响当前会话判断。

**修改：** `src/core/review-navigation.ts` 支持序列化，不再按上述 TTL/数量清除；`src/main.ts` 将选择写入插件 `selections.json`。读取必须携带窗口 sessionId，再校验 run 所属会话。真正缺失、清除或不匹配时提示准确原因，面板提供重试和返回本会话。

### 卡片缺失

**代码事实：** 旧关联要求最终回复文本指纹、时间差小于三秒、已结束且有非零差异；消息内容形态变化、停止状态、净零和绑定丢失均可能被过滤。不能据此断言每次现场消失都有同一原因。

**修改：** 新增只读原生历史证据导入，优先 userMessageId/replyMessageId，允许显式绑定的停止记录；净零事件保留。渲染不再以 string content 作为订阅前提，故障继续重试，已验证缓存保留。旧快照兼容匹配仍存在，缺少稳定身份时不随意合并。

### 浮窗不出现

**已观察事实：** 旧诊断显示插槽确实挂载过；运行状态识别依赖可见用户消息 ID/时间，宿主消息列表有窗口边界，采集原先仅覆盖 Write/Edit。缺少活动身份或没有捕获记录会隐藏浮窗。

**仍未证实：** 用户每次看不到浮窗的直接原因是否为消息窗口缺项、实际任务接口差异或布局/时序问题。没有原生复现，不把这些推测写成已修复事实。

**修改：** 主动同步会话身份与运行元数据，传递 taskId；后台优先匹配明确用户 ID。保留 generation/会话/迟到响应保护。只有内部 turnId 而没有可验证用户身份时仍保守隐藏，不将旧轮次冒充当前轮次。

### Git 与会话混淆

**修改：** 生产 Panel 默认是所属会话轮次，无 sessionId 不退回全局。Git 管理使用独立组件/适配器，不把整个仓库的工作区差异写入会话历史；通用旧差异组件的浏览器回归已迁移独立测试 harness，不削弱生产隔离。

## 能力边界与后续原生验收

- Shell 扫描最多 256 文件、4096 目录项、16 MiB 文本及约 3 秒预算；拒绝凭据、私有目录、链接和特殊路径。路径安全排除与扫描预算不是完整审计。
- 未完成 Task 租约不自动过期，可能使后续同根采集持续不确定；不能以任意超时将其变成确定作者。达到未解决租约上限时停止新捕获。
- 历史只读 JSONL、原生快照及结构化差异，以哈希验证；不读当前工作文件/Git 补造旧内容。不同来源无稳定用户 ID 时无法保证合并成唯一轮次，不做猜测性去重。
- Git hooks/filters 属于用户仓库受信任代码；提交仅使用已暂存内容。失败抛出错误，不自动重试写操作。stash pop 冲突保留 stash。
- 下一步原生验收必须在专用目录/会话人工安装并授权 1.3.0，然后完成：两会话共目录交替和并行窗口；运行修改时观察浮窗；结束/停止后卡片；刷新/重载后文件跳转；窄屏及输入高度变化。未完成这些步骤前不要标记整体交付通过。
