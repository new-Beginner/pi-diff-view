# 在最终回复末尾查看文件变更

> **v1.2.0：运行时输入框上方显示变更胶囊，结束后由文末卡片承接。** 已完成浏览器和真实插件快照服务自动化验收；未自动安装或执行原生宿主点击验收。详细说明见 [运行任务浮窗](running-changes.md)。下方 2026-10-10 验证数字为历史记录。

## 使用方式

1. 保持新版插件启用。运行中有可靠采集净变更时，输入框正上方显示胶囊；点击直接打开本次任务右侧只读 diff。结束/停止后隐藏，保留文末卡片。“原生审阅预检”旧入口不恢复。
2. 在**加载新版 Agent 扩展后开始的新任务**中，让 Agent 使用 Write/Edit 修改一个普通文件。运行中升级插件会导致 generation 变化，不能补造当时的 before 或最终回复关联；旧任务仍可在视图中只读查阅。
3. 任务结束后，最终回复末尾显示“已编辑 N 个文件”、本次净增删行数及首批最多 40 个文件（长元数据可能因传输预算减少首批数量）；没有净变化时不显示空卡片。无法唯一匹配最终回复、用户任务边界不明或旧版记录也不伪造卡片。
4. 点击文件名：打开右侧工作面板的 **Diff view / 差异审查** 插件页签，选择该任务与该文件。点击“查看变更”选择该任务的首个文件；不是宿主原生审阅，也不是居中浮层。
5. 仅使用客户端原有的“展开完整内容／收起内容”，没有插件自己的第二个折叠入口。收起时列表可在限高区域滚动，表头固定；展开后按文件数量完整显示，没有卡片内部滚动条。超出首批的元数据按有界分页自动续载；失败停止自动加载，可点击“加载更多文件”重试。“查看变更”仍可打开该轮次全部文件。

## 文件来源与限制

- 汇总只来自本次用户任务的真实支持工具快照，不混入 Git 全部未提交变更。同一文件按首次 before → 最终 after 合并；改完又还原的净零路径被省略。
- 工作区外普通文件必须是 Write/Edit 明确触及的绝对路径，显示完整路径和“工作区外 · 只读”。不扫描磁盘、不推测 Bash 修改，不授予父目录读写权限；外部文件没有撤销、重做或暂存操作。
- 凭据、宿主/插件私有数据、依赖目录、UNC/设备/ADS 和链接祖先被拒绝。非文本、超限、缺失内容仅显示元数据，行数不冒充完整统计。
- Bash、自定义工具、子代理、失败或迟到事件会令归因不完整。卡片可显示已经可靠采集的路径，并解释遗漏；完整归因要求未满足时禁止恢复。
- v1 历史仍可只读审阅，但不重构用户边界、外部文件来源或文末卡片。

## 侧栏跳转与排错

宿主没有公开 renderer“打开插件页签”操作，因此复用已加载主模块的 store `R` 和 React，并核验接口结构/身份。页签使用稳定 DTO，不依赖已变化的 minified 工厂导出。只打开 `plugin:local.diff-view/review`；不读取聊天正文、历史或数据库，不改消息和宿主输入框。接口不匹配时拒绝跳转，不回退其他窗口。历史原生预检的三个固定资源哈希不是当前插件侧栏的门槛。

选择仅保存在插件内存，最多 32 个会话、30 分钟有效。传给视图的是不含内容或文件路径的 UUID 令牌；首次经 `piViewOpen`、后续经 `view:open {path}` 传递。会话切换使旧会话令牌暂时无效，视图定期核对；重载、清历史或过期后需要重新点击卡片。

| 错误 | 处理方式 |
|---|---|
| `SIDEBAR_CONTRACT` | 宿主接口不匹配；停止自动跳转，提供错误供兼容修复，不更改安装文件 |
| `SIDEBAR_SESSION` | 回到卡片所属会话后重新点击 |
| `SIDEBAR_VIEW` | 检查本插件已启用且已授予 ui.view；权限由用户批准 |
| `NAVIGATION_EXPIRED` | 重新点击文末卡片，不猜测旧选择 |
| 快照或汇总不可用 | 读错误说明；不能用当前磁盘文件冒充历史 before/after |

侧栏复用原有 diff、评论、复制和受保护操作。独立视图桥接无法直接回填输入框，评论反馈由用户复制粘贴后手动发送；已有草稿保持不变。

### 卡片不出现修复（2026-10-10）

只读诊断发现：采集已有两个文件和最终回复，renderer 插槽已挂载，真实查询却未绑定。核对本机 0.17.0 实现后确认，`entryExtra` 的 `message.content` 是任务内所有助手文本各自 trim 后以两个换行连接的内容，不能拿整段哈希与单条最终回复哈希相等比较。

修复仅匹配段落边界后的完整最终回复末尾，保留原有会话、3 秒时间窗口、唯一任务及唯一界面消息绑定校验。不用包含关键词或模糊匹配，不回填聊天正文。renderer 只传序列化后不超过 24 KB 的末尾，避免长进度令整张卡片被跳过；最终回复本身超限或候选段落超过预算时仍保守拒绝。每轮优先查询最新回复，再轮询旧回复。

新增复现用例在旧代码上失败、修复后通过。开发宿主自身记录确认：上轮两文件记录的 bindings 从空变为对应最终界面消息 ID；未读取宿主数据库，未手动修改采集或绑定数据。临时逐条查询诊断已移除，保留 `reply-slot-mounted`、`card-bound`、`card-query-error` 阶段标记，不存聊天正文。

这证明真实匹配已恢复，不等同于 GUI 显示和侧栏点击验收。仍需回看上轮最终回复卡片，点击第二个样本文件，核对右侧 diff。
